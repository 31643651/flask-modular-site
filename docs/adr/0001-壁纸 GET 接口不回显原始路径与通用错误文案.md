# ADR-0001: 壁纸 GET 接口不回显原始路径与通用错误文案

## 状态

已接受（accepted，2026-11-13，最终审查修复轮 I3 实施）

## 背景

最终审查（Important-3）发现 `Module/index/index.py` 两个低危信息泄露：

1. **GET 接口路径泄露**：`GET /api/wallpaper/config` 是匿名公开接口（首页渲染用）。当壁纸功能开关关闭但管理员已配置了原始服务器路径时，响应会把配置里的原始服务器路径（如 `static/wallpaper_files`）原样回显给任意匿名访问者——泄露服务器目录结构，可被用于侦察。只有"enabled 且 path 非空"时才被替换为公开路由 `/static/wallpaper`。
2. **错误原文回显**：`get_wallpaper_config` / `update_wallpaper_config` / `get_mounted_pages_public` 三处 `except Exception as e` 分支把 `str(e)` 直接放进响应 message 回显，可能泄露内部实现细节（文件路径、库异常文本）。

约束：
- 响应结构必须兼容：前端（index.html，他人未提交改动不可触碰）读取 `path` 与 `enabled` 两个键，不得新增/删减键。
- C3 已落地的 POST 鉴权三级校验（401/403/302）与 enabled 强转不得回退。
- spec（docs/specs/index.md 契约 6）已锚定"公共只读接口不泄露敏感路径"，本修复是让实现回归该锚点。

## 决策

1. **GET 路径遮蔽**：`get_wallpaper_config` 在返回前，若 `enabled` 为假或 `path` 为空，把响应中的 `path` 置为空字符串 `""`（不回显原始服务器路径）；仅当"enabled 且 path 非空"时维持现状返回 `/static/wallpaper`。键集合不变（success/enabled/path）。
2. **通用错误文案**：三处 `except Exception` 分支的响应 message 统一改为固定通用中文文案"服务器内部错误，请查看日志"，不再回显 `str(e)`；同时在每个分支补 `logger.error` 记录原始异常（与文件内 `serve_wallpaper` 等异常分支风格一致），保证可诊断性不丢失。
3. **放弃的备选**：
   - "未启用时删掉 path 键"——破坏前端兼容（前端直接读 `data.path`），放弃；
   - "按异常类型选择性回显"——增加复杂度且仍可能泄露，放弃；
   - "把 GET 接口改为登录后可见"——首页匿名渲染依赖该接口，破坏公共门面语义，放弃。

## 后果

- 正面：匿名访问者不再能获得服务器原始目录路径；异常信息不再泄露内部细节；与 spec 契约 6 对齐。
- 负面/代价：响应中 `path` 字段在"功能开但关、已配 path"状态下的取值发生变化（原为原始路径，现恒为 ""）——属于行为变更，但该值本就不应外泄；诊断需查日志而非响应体。
- 对既有契约/goldens 的影响：无 goldens 覆盖壁纸 GET，无需改 golden；C3 的 `tests/test_wallpaper_api.py` 中 POST 403/鉴权/强转测试不受影响；新增 GET 行为断言。
- 风险与缓解：前端在"关闭但已配 path"场景下读到的 path 为空——该场景下壁纸本就不展示（enabled=False 前端即不渲染），无可见行为差异。
