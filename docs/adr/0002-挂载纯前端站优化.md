# ADR-0002: 挂载纯前端站优化

## 状态

已接受（accepted，2026-11-16，"挂载纯前端站优化"计划任务 1 建档，先于一切代码）

## 背景

挂载功能（`GET /<page_name>`，`Module/index/index.py`）对纯前端构建产物（Vite/CRA 等 SPA dist）失效。调研三个真实项目并核实其部署产物，确认了三种资源引用形态：sdinspector（ImageMeta，Vite `base:'./'`，相对引用 `static/*` + PWA）、it-tools（Vite `base:'/'`，绝对引用 `/assets/*-hash.js|css` + `/manifest.webmanifest`，挂到子路径必 404）、excalidraw（绝对引用 + 运行时 JS 动态拼绝对路径 fetch 资源，服务端无法兜底）。

归纳出三个根因：其一，相对引用在无尾斜杠 URL（`/name`）下被浏览器解析到站点根（`/static/...`），撞上本站 Flask static 路由而 404；其二，`.js/.css` 的 MIME 依赖 `mimetypes.guess_type`（Windows 注册表敏感），而 `<script type="module">` 受浏览器严格 MIME 检查，MIME 错误即拒绝执行；其三，config.json 中 sdinspector 的挂载路径写着 `Module/sdinspector` 而实际目录在根目录 `sdinspector/`（数据断裂，不属于代码决策，随部署修 config.json）。

约束：既有安全校验（路径穿越拒绝、敏感目录检查、`relative_to` 兜底）不得降级；`docs/specs/index.md` 契约 5 已锚定挂载行为，本次属对外可观察行为变更，故先立本 ADR 再动手。

## 决策

三块改动，全部落在挂载服务侧（`Module/index/index.py`）。第一，保留既有目录挂载的尾斜杠重定向（index.py L346-348），并补齐子目录 index.html 分支的同形态重定向——`GET /<page_name>` 命中已挂载目录且无子路径时 302 到 `/<page_name>/`，使浏览器相对资源解析基准变为 `/name/`，相对引用由既有 subpath 文件服务接管；带尾斜杠访问直接服务 index.html 不重定向。第二，`serve_static_file` 增加显式扩展名→MIME 映射表（`.js/.mjs→text/javascript`、`.css→text/css`、`.svg/.wasm/.woff/.woff2/.json/.webmanifest` 等），`guess_type` 仅作未命中表项时的兜底，消除 Windows 注册表敏感性。第三，服务挂载 HTML 时把双引号 `src="/..."`/`href="/..."` 中站根绝对引用重写为 `/<name>/...` 前缀路径——排除 `//` 协议相对、裸 `/`、外链 `http(s)://`、`data:`、`#` 锚点，相对引用不动；采用保守正则只匹配双引号形态（单引号、无引号形态宁可漏改不误改），不引入 HTML 解析器依赖，且仅对挂载页 HTML 生效，不影响本站模板。

放弃的备选：`<base>` 注入——会改变页内全部相对链接的解析基准，风险面大，且对绝对引用无效，故不采用。

## 后果

挂载页的 302 重定向行为、HTML 响应内容（被重写）、静态资源 MIME 三者成为对外可观察行为，均由本 ADR 备案并为后续实现与测试（fixture 三形态 + 真实构建包）提供依据。兼容范围之外的两类站点作为限制备案：运行时 JS 动态拼绝对路径 fetch 资源的站点（excalidraw 型）与 history 路由 SPA 的深链接（无 SPA fallback）不在本次兼容范围。挂载路径配置断裂（sdinspector `Module/sdinspector` → `sdinspector`）不属于本 ADR 的代码决策，随部署修 config.json（数据文件不入 git）。`docs/specs/index.md` 契约 5（页面挂载）将随收尾任务更新，与实现同步。
