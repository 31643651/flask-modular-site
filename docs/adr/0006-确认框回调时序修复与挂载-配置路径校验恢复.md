# ADR-0006：确认框回调时序修复与挂载/配置路径校验恢复

- 状态：已接受
- 日期：2026-11-20

## 背景

用户报告三类症状：日志清除按钮无效果（"断链"）、挂载页面删除失效、全站多处"死按钮"。

根因调查（2026-11-20）：

1. **确认框回调时序错误**：8 个模板（activity.html、activity_all.html、config.html、users.html、userfix.html、dashboard.html、favorites.html、index.html）的 `confirmDialog()` 均为先调 `closeDialog()`（将 `dialogCallback` 置 null），随后才判断 `if (dialogCallback)`。回调永远为 null，所有 `showConfirm` 确认框点击"确定"都不执行后续动作。这覆盖了日志清理、挂载删除、用户删除/禁用、服务器重启、解除封禁、用户反馈处理等全部确认类操作。
2. **挂载/配置路径校验在模块化重构中丢失**：历史安全修复 `be033be`(H1 挂载路径白名单)、`a4713d4`(H13 系统敏感路径白名单)、`aff91cf`(S4 配置路径空值/类型校验)、`dcdcdc9`(M39 配置路径存在性校验) 均写在 `Module/admin/admin.py`；该文件在 `f79b372` 重构中被拆分删除，校验逻辑未迁移到 `Module/core/admin_service.py`：
   - `add_mounted_page` 丢失：名称格式校验、路径存在性校验、系统敏感路径白名单、文件必须 HTML、挂载数量上限、重名检查；
   - `update_config` 丢失：配置键白名单、路径空值/类型/存在性校验，现为 `current.update(new_config)` 裸合并，可写入任意顶层键；
   - `remove_mounted_page` 丢失："页面不存在"判定，现在对任意名称恒返回成功。
3. **服务端挂载路径白名单（be033be）仍在** `Module/index/index.py`，未丢失；本次恢复的是写入侧（添加/配置更新）校验。

对外可观察行为变化点：确认框点"确定"后动作开始执行（此前静默失败）；添加挂载与配置更新的失败分支增多（非法名称/不存在路径/敏感路径/未知配置键返回 `success: false`）；删除不存在的挂载页面由"成功"变为失败提示。

## 决策

1. **修复确认框时序**：`confirmDialog()` 先将 `dialogCallback` 保存到局部变量，再调用 `closeDialog()`，最后用局部变量触发回调。8 个模板同步修改，保持各模板既有代码风格（`var`/`const` 混用处沿用原样）。取消按钮仍走 `closeDialog()`，回调被丢弃（不执行动作），行为与预期一致。
2. **恢复写入侧校验**，落点在 `Module/core/admin_service.py`（服务层，路由层不重复实现）：
   - `add_mounted_page`：恢复名称格式（ASCII 字母/数字/下划线/短横线）、路径存在性（相对路径相对项目根）、系统敏感路径白名单（`SENSITIVE_PATHS`：Windows/Unix 系统目录）、文件必须 `.html`、挂载数量上限 20、重名拒绝；
   - `update_config`：恢复配置键白名单（`paths.*` 三键、`wallpaper.{enabled,path}`、`mounted_pages` 数组上限 20）与路径空值/类型/存在性校验；
   - `remove_mounted_page`：恢复"页面不存在"判定，返回 `(False, "页面不存在")`。
3. **状态码保持 200 + `{success, message}`**（与既有挂载 API 失败分支口径一致，`routes_config.py` 现状即如此），不恢复历史版本的 400——历史 400 属重构前行为，恢复会扩大变更面且与当前前端 `response.json()` 处理逻辑不匹配。
4. **放弃的备选**：在路由层加校验（会造成服务层与路由层双重校验、且其他调用方拿不到保护）；修改 `closeDialog` 不置空回调（会让"取消"也触发旧回调，产生误执行）。

## 后果

- 正面：确认类按钮恢复可用，日志清理/挂载删除/用户管理等操作重新生效；挂载与配置写入侧恢复安全校验，防止挂载系统敏感路径与任意配置键注入。
- 负面与代价：8 个模板重复修改，需模板级测试锚定时序防止回归；`admin_service` 校验逻辑变长，需单元测试覆盖各失败分支。
- 对既有契约的影响：`admin_mounted_page_add.json` 五键成功结构不变；失败分支仍为 `{success, message}` 且不携带跳转字段，契约不改、golden 不改。现有挂载测试使用不存在的 `D:/test/page.html` 断言成功，恢复存在性校验后需同步改为真实临时文件路径——属测试数据适配新校验，非放宽断言。
