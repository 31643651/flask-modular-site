# SPEC：userfix（用户修复模块）

> 本文件只锚定意图与对外承诺，不写实现细节。实现细节见 docs/architecture.md。

## 这个模块存在是为了什么

用户向站长反馈问题的通道：提交 Bug/建议（文字+截图），站长在后台处理并跟踪状态。

## 对外承诺的行为契约（用户视角可观察）

1. **提交配额（bug #18 锚定）**：非超级管理员每日最多 3 次提交（含普通管理员与普通用户）；仅超级管理员（uid 0-9）不限次；**配额只在提交成功时扣减**——被校验拦截（空文本/超长/图片数量或大小超限）或被限流的提交不扣减配额。
2. **提交内容组织**：提交按"用户名_时间戳"目录组织，含 metadata.json（元数据）与 content.txt（正文）、图片文件；提交保留 30 天自动清理。
3. **提交 ID 校验（C1 锚定）**：管理接口对 submission ID 做黑名单校验（禁止路径分隔符/点号/空白与控制字符）+ resolve 后必须仍在提交目录内；非法 ID 的更新/删除被拒绝且无文件系统副作用。
4. **元数据读写规范（C5 锚定）**：metadata.json 经 file_utils 线程安全函数读写（原子写）；文件损坏时列表跳过该记录、更新返回明确失败，不崩溃。
5. **状态管理**：后台可按状态筛选（unprocessed 等）、分页浏览、更新状态、删除（删除整个提交目录，目录外目标不可达）。
6. **图片服务**：提交图片经 `GET /userfix/image/<id>/<filename>` 服务；仅服务白名单位图扩展（jpg/jpeg/png/gif/webp/bmp），扩展非白名单或文件内容与扩展名不符时不服务（404），响应 MIME 按扩展显式固定。

## 边界与豁免

- 提交端对登录用户开放；查看/管理端仅超级管理员。
- 配额计数存于 userfix_limits.json（按天），提交内容目录已 gitignore。
