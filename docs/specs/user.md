# SPEC：user（用户模块）

> 本文件只锚定意图与对外承诺，不写实现细节。实现细节见 docs/architecture.md。

## 这个模块存在是为了什么

身份与认证：登录、注册、管理员二次验证、个人资料——是全站鉴权体系的入口。

## 对外承诺的行为契约（用户视角可观察）

1. **登录**：凭用户名/密码登录；登录失败有明确提示；连续失败达到阈值被限流拒绝。
2. **CSRF token 轮换（B6 锚定）**：登录成功后 session 中 CSRF token 重新生成（旧 token 失效），并同步写入非 httponly cookie 供前端 JS 读取；不存在跨请求保留旧 token 的行为。
3. **超级管理员二次验证**：启用开关后，超级管理员（uid 0-9）登录需先通过动态验证码验证才能进入站点；验证关闭时自动视为已验证。普通管理员（uid 11-99）与普通用户一致，登录无需动态验证。
4. **注册**：新用户注册；用户名占用检查（`/user/api/check-username`）。
5. **登出**：登出需 CSRF 校验（防跨站登出），成功后回登录页。
6. **资料页**：仅登录用户可见；会话中用户失效（被禁用/删除）时清空会话回登录页。

## 边界与豁免

- 登录/验证/注册页在认证白名单内，可未登录访问。
- 密码存储为哈希；明文历史数据在验证成功时自动迁移。
