# SPEC：setup（初始配置模块）

> 本文件只锚定意图与对外承诺，不写实现细节。实现细节见 docs/architecture.md。

## 这个模块存在是为了什么

首次部署的开箱引导：确保站点在没有任何配置时能通过浏览器完成初始化，而不是抛错或暴露未配置状态。

## 对外承诺的行为契约（用户视角可观察）

1. **强制引导**：config.json 未生成时，所有请求被全局中间件重定向到 `/setup`；站点在完成初始化前不可用。
2. **两步向导**：
   - 步骤 1：创建管理员账户（用户名固定 `admin`，两次密码校验），可选启用管理员二次验证开关；
   - 步骤 2：设置服务器名称，生成 config.json 默认结构（paths、settings、wallpaper、mounted_pages、server_name），清理 session 并回登录页。
3. **完成即锁定**：config.json 已存在时访问 `/setup` 直接重定向登录页——向导不可重复进入。
4. **管理员账户落库**：步骤 2 创建的用户写入 users 表（id=1、role=admin、is_superadmin），密码为哈希存储。

## 边界与豁免

- `/setup` 在认证与 CSRF 豁免名单内（初始化时尚无会话体系）。
- 生成失败不产生半成品配置（配置写入失败时向导不进入完成态）。
